# 발표용: 항목별 비용 계산 방식, 파라미터 값, 근거 (2026-10-09)

> **우리 설계 기준**: "무거운 박스를 가벼운 박스 위에 두지 않는다" 규칙은 쓰지 않습니다.
> 대신 **박스별 허용 하중 + 누적 하중 검사**와 **기둥 전체 0.3 g 검사**를 씁니다.
>
> **근거 표시**
> - [실험] 우리 시뮬레이션 실험으로 정한 값
> - [측정] 로그·시뮬레이터에서 잰 값
> - [문헌] 업계 표준이나 공개 자료
> - [가정] 현장 값이 없어 논리적으로 정한 값 (현장 값으로 바꾸는 방법 포함)
> - [팀] 팀 시뮬레이터의 기존 값
>
> **결과 수치 주의**: 지금까지 낸 비교 결과(팔레트 −13%, 시간 −17%)는 팀의 무게 순서 규칙을 **켠 상태**에서 같은 조건으로 비교한 값입니다. 우리 설계 기준(규칙 끔 + 기둥 0.3 g 검사)의 결과는 검사를 구현한 뒤 다시 실험해 채웁니다(10장).

## 1. 무엇을 최소화하나: 현장 비용 J
**발표 문장**: "현장이 실제로 지불하는 시간과 팔레트 비용을 하나의 기준으로 합쳐서 판단했습니다."

```
J = 총 작업시간 + 팔레트 1개 환산 시간 × 사용 팔레트 수
총 작업시간 = 로봇 동작 + 버퍼 이동 + 재적재 + 팔레트 교체 + 컨베이어 정지·대기
```

- **중복 방지**
  - 교체 시간은 작업시간에만 넣습니다.
  - 빈 공간 손실은 팔레트 수에 이미 들어 있으므로 따로 더하지 않습니다.
- **보고 방식**: 합산값 J만 보고하지 않고, 시간과 팔레트 수를 항상 따로 함께 보고합니다.

### 1-1. 팔레트 교체 시간 [가정 → 계산식]
```
교체 시간 = 반출·빈 팔레트 투입 + 셀에서 랩 감는 시간 + 지게차 대기
지게차 대기: 지게차 1대가 셀 n대를 맡을 때
  가동률 ρ = n × 처리시간 ÷ 팔레트 배출 간격,  대기 = ρ × 처리시간 ÷ (1 − ρ)   (대기열 공식)
```
| 입력 | 기준값 | 근거 |
|---|---|---|
| 반출·투입 | 60 s | [팀] 팀 시뮬레이터 교체 시간 |
| 셀에서 랩 | 0 s (다른 곳에서 감음) | [가정] |
| 지게차 처리시간 / 배출 간격 | 180 s / 900 s | [가정] |
| 지게차 1대당 셀 수 | 1 | [가정] 4대면 대기 때문에 교체 시간이 780 s |

### 1-2. 팔레트 1개 환산 시간 [가정 → 계산식]
```
팔레트 1개 비용 = 트럭 칸 값(운임 ÷ 트럭당 팔레트 수) + 지게차 작업비 + 랩 필름
환산 시간 = 팔레트 1개 비용 ÷ 셀 1초 비용
```
- 팔레트 자체 가격은 넣지 않았습니다. 공장에 충분히 있다고 봤습니다.

| 입력 | 기준값 | 근거 |
|---|---|---|
| 트럭 운임 / 트럭당 팔레트 | 30만 원 / 14개 | [가정] 11톤 윙바디(적재함 약 9.6 × 2.35 m)에 1.1 m 팔레트 바닥 적재 시 약 16개 → 여유를 두고 14개 |
| 지게차 비용 | 3.5만 원/시간 × 3분 | [가정] |
| 필름 | 500원 | [가정] |
| 셀 1초 비용 | 10원 | [가정] 설비 상각 + 운영비 |
| **결과** | **2.37만 원 → 2,368 s** | 팀 보상 비율(팔레트 1개 = 2,000 s)과 비슷 |

**발표 Q&A: 이 값이 틀리면요?**
- 여섯 입력을 **하나씩** 바꿔 봤습니다(`10_site_params/site_oat.md`).
  - 교체 시간: 60~780 s
  - 팔레트 환산: 1,082~5,225 s
- 그래도 팀 대비 −13.5~14.2%, 54번 중 54번 이겼습니다.
- 제안 방식은 시간과 팔레트를 **둘 다** 줄이기 때문에 결론이 바뀌지 않습니다.
- 현장 값이 바꾸는 것은 절감량뿐입니다. 예: 운임이 12만 원에서 70만 원이 되면 주문당 절감이 1,029 s에서 4,174 s로 늘어납니다.

| 파라미터 | 값 | 근거 |
|---|---|---|
| 안정성 기준 | 랩 없이 수평 0.3 g (경사대 16.7°) | [계산+문헌] 랩 전 지게차 서행·랩핑기 회전 시 0.1~0.2 g (계산) → 1.5~2배 여유. 운송 0.5 g(EUMOS 40509)는 랩이 감당. 상세 `STABILITY_0_3G_BASIS.md` |
| 검사 범위 | **기둥 전체**: 접촉면마다 그 위 박스 전체의 합성 무게중심 | [실험] 쓰러진 박스의 81%가 높은 기둥 위에 있었습니다. 박스 하나만 보면 30 cm 4단 기둥이 1.0 g로 통과하지만, 기둥 전체로는 0.25 g라 불통과입니다 |
| 마찰계수 | 0.4 (민감도 0.3·0.5) | [문헌] 골판지끼리 0.3~0.5 중 보수값. 시뮬레이터 기본값(0.64)은 낙관적이라 쓰지 않습니다 |
| 힘 평형 검사 여유 | 0.35 g | [가정] 0.3 g + 계산 오차 여유 |
| 검증 | PyBullet 흔들림 시험 0.1~0.6 g | [측정] 계산 검사가 놓친 위험 비율을 보고합니다 |

**검사 3단계**
1. 무게중심 검사: 모든 후보에 적용합니다. 빠릅니다.
2. 마찰을 포함한 힘 평형 계산: 위험해 보이는 후보에만 적용합니다.
3. 물리 시뮬레이션: 검증용입니다.

## 3. 하중: 박스별 허용 하중 + 누적 하중 (무게 순서 규칙 대신)
**발표 문장**: "무게 순서 대신, 박스마다 버틸 수 있는 하중을 계산하고 위에 쌓인 무게의 합으로 검사했습니다."

```
허용 하중 = 박스 압축강도 × 습도 계수 × 보관기간 계수 × 적재 편차 계수 ÷ 잔여 안전계수
박스 압축강도 = 5.87 × 판지 강도(ECT) × √(두께 × 박스 둘레)     (McKee 식)
검사: 아래 박스가 받는 하중(위에 쌓인 모든 박스의 무게, 접촉 면적 비율로 분배) ≤ 허용 하중
```

| 파라미터 | 값 | 근거 |
|---|---|---|
| 판지 등급 | ≤5 kg B골 (ECT 4,250, 3 mm) / ≤15 kg C골 (5,250, 4 mm) / 그 이상 BC 이중골 (8,500, 7 mm) | [가정+팀] 무거운 제품일수록 튼튼한 판지를 씁니다. ECT는 팀 판지 등급 범위의 중간값입니다 |
| 습도 계수 | 50% 1.0 / 70% 0.80 / 80% 0.68 / 90% 0.48 | [문헌] 골판지 업계 경험값 |
| 보관기간 계수 | 10일 0.63 / 30일 0.59 / 90일 0.55 | [문헌] 〃 |
| 적재 편차 계수 | 0.8 | [문헌] 범위 0.6~0.9 중 중간 |
| 잔여 안전계수 | 1.5 | [가정] 위 계수가 이미 감소분을 반영하므로 남은 불확실성만 봅니다(사용자 승인) |
| 결과 (일반 창고) | B 42~45 kg, C 67~79 kg, BC 172~202 kg | 기존 팀 값은 판지 구분 없이 37~58 kg |

- **출처 우선순위**: 공급사 압축시험값 → 사양서 판지 등급 → 무게 등급 추정(현재)

**발표 Q&A**
- **무게 순서 규칙을 왜 안 쓰나요?**
  - 가벼워도 튼튼한 박스, 무거워도 약한 박스를 구분하지 못합니다.
  - 현대 관계자 피드백도 박스별 허용 하중 방향이었습니다.
- **무게 순서 규칙을 끄면 안정성이 떨어지지 않나요?**
  - 실험에서 실제로 떨어졌습니다(0.3 g 통과 75% → 34%). 이 규칙이 무게중심을 낮추는 역할도 했기 때문입니다.
  - 그래서 기둥 전체 0.3 g 검사를 함께 넣습니다.
- **판지가 극단적으로 약한 현장이면요?**
  - 숨은 극한 조건(얇은 판지, 젖음, 파손 10%)에서는 어떤 방식도 막지 못했습니다(주문당 10~14개 찌그러짐).
  - 현장의 습도와 보관 기간을 입력받아 계수에 넣고, 파손 박스는 감지해서 따로 빼야 합니다.

## 4. 자리 평가 점수 (어디에 놓을지)
**발표 문장**: "안정성은 '충분한가'가 중요하므로, 기준 미만은 크게 깎고 기준 이상은 조금만 더했습니다. 충분히 안정하면 그다음은 효율로 경쟁합니다."

```
점수 = 비선형(안정성 S) + 비선형(하중 여유 L) − 효율 비용 − 미래 비용
비선형(x) = 기준 미만: 큰 기울기 × x,  기준 이상: 작은 기울기 × 초과분
```

| 파라미터 | 값 | 근거 |
|---|---|---|
| 안정성 S 구성 | 받침 0.20 + 맞물림 0.25 + 흔들림 0.40 + 옆면 지지 0.15 | [가정] 쓰러짐 실패 분석에서 흔들림 요인이 가장 커서 비중을 가장 크게 줬습니다 |
| S 기준 / 기울기 | 0.75 / 미만 20, 이상 2 | [실험] 0.6·0.9, 10·40은 0.3 g 통과율이 5%p 넘게 떨어져 탈락했습니다 |
| 하중 여유 L | 1 − (가장 많이 눌리는 아래 박스의 하중 ÷ 허용 하중) | 하드 검사는 넘는 자리만 막고, 이 점수는 한계 직전 자리를 피하게 합니다 |
| L 기준 / 기울기 | 0.5 / 미만 8, 이상 0.5 | [가정] 허용 하중의 절반을 여유로 남깁니다 |
| 효율 비용 가중치 | 높이 2, 윗면 평탄도 2, 울퉁불퉁 2, 빈틈 1.5, 모서리 4, 무게 차단 1.5, 바닥 소모 0.5 | [가정] 손으로 정한 값입니다. 학습 단계에서 "최종 적재율 예측 모델"로 대체합니다 |

## 5. 미래 비용 (앞으로 올 박스를 고려)
**발표 문장**: "컨베이어에서 미리 잰 박스와 남은 주문 수량으로 앞으로 올 순서를 여러 개 만들어 보고, 평균과 최악을 함께 봤습니다."

```
미래 비용 = γ × [(1 − κ) × 시나리오 평균 비용 + κ × 최악 시나리오 비용] + 막힘 벌점 × 막힘 확률
```

| 파라미터 | 값 | 근거 |
|---|---|---|
| 미리 아는 박스 | 계량 완료 3개 + 상류 카메라 2개 | [실험] 0개에서 3개로 늘릴 때 팔레트 감소 효과가 대부분 생깁니다(−8% → −14%). 그 이상은 이득이 작습니다. 계량대 위치를 정하는 근거입니다 |
| 미래 탐색 깊이 | 5박스 (시간 부족 시 3박스) | [실험] 판정 1회 429 ms vs 174 ms. 3박스는 비용 +1.8% |
| 시나리오 수 / 후보 수 | 4 / 4 | [실험] 2·8, 2·6은 탈락 |
| 최악 비중 κ | 0.3 | [가정] 운 나쁜 순서 대비. 학습 단계에서 재조정 |
| 미래 할인 γ | 0.6 | [가정] 먼 미래일수록 불확실합니다 |
| 막힘 벌점 | 6 | [가정] 놓을 곳이 없어지는 상황을 피하게 합니다 |

- 트리 탐색(MCTS)과 학습 모델은 다른 팀원이 진행 중입니다. 이 미래 비용과 J를 평가 기준으로 공유합니다.

버퍼 사용 비용 = 버퍼 이동 로봇 시간 + 꺼낼 때 다시 이동하는 시간  (J의 작업시간에 포함)
버퍼에 넣는 조건: 지금 놓는 것보다 미래 비용 포함 J가 버퍼 비용보다 많이 줄어들 때

|---|---|---|

| 비상칸 | 0칸 (4칸 모두 사용) | [실험] 1칸을 남기면 0.3 g 통과율이 떨어졌습니다 |

## 7. 재적재·재배치 (이미 놓은 박스나 버퍼 박스 옮기기)
**발표 문장**: "공간이 없을 때만 옮기는 게 아니라, 옮겨서 얻는 이득이 모든 비용을 빼고도 남을 때만 옮깁니다."

```
순이득 하한 = (옮긴 뒤 J 감소량의 보수적 추정)
             − (로봇 이동 시간 + 다른 작업 중단 + 컨베이어 정지 + 임시 보관 + 재검증 시간)
순이득 하한 > θ 일 때만 실행
```
- **중복 방지**: 로봇 시간은 작업시간 J에 한 번만 넣습니다.

| 파라미터 | 값 | 근거 |
|---|---|---|
| 재적재 1회 로봇 시간 | 12 s | [팀] 실측 전 가정값. 로봇 시간 모델 값이 주어지면 교체합니다 |
| θ (최소 순이득) | 0 (임시) | [실험] 팀 방식 기준 0.05는 14승 5패였지만 유의하지 않았습니다(p = 0.064). 위의 순이득 방식을 구현한 뒤 재실험합니다 |
| 결과 | 주문당 재적재 약 0.4회 | [실험] |

## 8. 팔레트 교체 (닫고 새 팔레트 vs 계속 채우기)
**발표 문장**: "팔레트를 닫을지는 교체 비용과, 계속 채울 때 드는 버퍼·재적재·대기 비용을 비교해서 정합니다."

```
닫는 비용 = 교체 시간 + 팔레트 1개 환산 시간 − (남은 박스를 새 팔레트에 더 잘 쌓아서 얻는 이득)
계속 비용 = 버퍼 이동 + 재적재 + 컨베이어 대기 + 남은 공간 낭비 위험
닫는 비용 < 계속 비용 이면 교체
```
