# AHEAD v3.3 알고리즘 (2026-10-09, v3.2 + 2차 GPT 검토 반영)

> v3.2를 대체합니다. v3.3 변경: 탐색 생략은 기본 끔(실험 후 활성), 후보 점진 확장, 의존성 추적 범위 확대, 컨베이어 정지 전제조건, 미리보기 수와 대기 가능 수 분리, 재배치 이득 하한 기준, 파라미터 4분류와 실험 순서(11장). 아래는 설계이며, 아직 구현·검증되지 않았습니다.

## 0. 요약
알려진 박스는 그대로, 모르는 미래는 시나리오로 놓고, **MCTS**로 "놓기·버퍼·교체" 행동 순서를 탐색합니다. 새 정보가 올 때마다 계획을 이어서 고치고(**롤링 호라이즌 / MPC**), 실행 시점에는 **이미 상세 검증이 끝난 행동만** 내보냅니다. **AI(가치·순위 모델)**는 탐색이 어디를 먼저 볼지와 그 뒤 결과를 예측합니다. 제약 검사를 대신하지 않습니다.

## 1. 목표
**제약 (모델 기반 검사)**: 기하(겹침·돌출·높이), SKU별 허용 하중(누적), 안정성(잠정 시험 목표, 8장), 로봇 실행 가능성(상세 IK·충돌)

**목적함수: 현장 환산 비용 (사용자 결정)**

```
J = c_t · T_total + c_p · N_pallet + c_h · N_intervene + c_u · N_unprocessed
```

| 항목 | 정의 | 비고 |
|---|---|---|
| `T_total` | 주문 전체 처리 완료시간 (놓기·버퍼 이동·재적재·팔레트 교체·대기 포함) | 교체 시간은 여기에만 넣고 다른 항에 중복하지 않음 |
| `N_pallet` | 출하 팔레트 수 | 빈 공간 손실은 팔레트 수에 이미 반영됨 → `(1 − 채움률)` 항을 따로 두지 않음 |
| `N_intervene` | 작업자 개입·정지 횟수 | |
| `N_unprocessed` | 미처리(NG 제외) 박스 수 | 결과에서 절대 빼지 않음 |
| `c_*` | 현장 설정 파일. 대회 기본값은 가정값으로 명시 | **민감도 분석**: `c_p/c_t` = 1,000 / 2,000 / 5,000 s, 교체 시간 60 / 120 / 180 s |

- 보고는 `T_total`, `N_pallet`, 개입, 미처리를 **항상 따로** 같이 냅니다. 합산값만 보고하지 않습니다.
- 마지막 트럭의 빈칸처럼 팔레트 수만으로 안 드러나는 비용은, 현장에서 근거가 주어질 때 추가합니다.

## 2. 입력 (확실성 구분)
| 정보 | 확실성 | 사용 |
|---|---|---|
| 현재 팔레트·버퍼 | 확정 | 그대로 |
| 실행 중인 행동 (집는 중인 박스, 잠긴 배치 공간·버퍼 칸) | 확정(진행 중) | 고정, 다른 계획에서 사용 금지 |
| 계량된 대기열 | 규격·무게·순서 확정, 도착 시각 추정 | 순서 고정, 시각은 범위 |
| 상류 CCTV 박스 | 규격·순서 확정, 무게 범위 | 시나리오마다 무게 샘플링 |
| 미입고 | SKU별 수량 | 순서 샘플링. 수량 정보가 없으면 그 범위에서만 |
| 현장 조건 | 설정 | 팔레트 규격, 버퍼 수, 로봇·그리퍼, 교체 시간, `c_*`, 컨베이어 정지 가능 여부, `queue_capacity`(기본 0) |

박스 ID로 관측, 계량, 집기, 결과를 연결해 중복 집계를 막습니다.

## 3. 계획 구조
| 구성 | 수정 가능 |
|---|---|
| 확정 상태 (놓인 박스, 버퍼 점유) | 불가 (옮기려면 재적재 행동 + 비용) |
| 확정 행동 (명령이 나간 행동 + 잠긴 공간) | 불가 |
| 작업 순서 (대기열 박스별 행동) | 가능 |
| 목표 배치도 (**현재 팔레트에 담을 박스 기준** 위치·방향·받침 관계) | 가능 (목표일 뿐) |

- **실행 가능본**: 다음 행동의 상세 검증까지 끝난 계획
- **작업본**: 탐색 중인 계획. 검증이 끝나고 상태 버전이 맞을 때 실행 가능본으로 승격합니다.

## 4. 탐색: MCTS + 롤링 호라이즌
- **행동**: 현재 박스 놓기(후보 위치별), 버퍼 맡기기, 버퍼 꺼내 놓기, 팔레트 교체, 제한된 재적재
- **후보 위치**: 기존 후보 생성기(`pac_candidates`: EMS ∪ Extreme Point) + 제약 검사

**MCTS** (미래가 확률적이므로, 시뮬레이션마다 미래를 하나 샘플링하는 determinized / open-loop 방식)
1. **선택**: PUCT. 학습 모델 사전 확률 + 지금까지 결과
2. **확장**: 점진적 확장(progressive widening). 빠른 평가·학습 순위 상위부터
3. **시뮬레이션**: 미래 샘플(대기열 고정, 상류는 무게, 미입고는 순서) → 빠른 기본 정책으로 H박스 진행 → 끝 상태는 가치 모델로 평가
4. **역전파**: `J`의 추정 증분 + 막힘·미처리. 평균과 나쁜 경우(하위 꼬리) 함께

**롤링 호라이즌**
- 새 관측이 오면 새 상태와 맞는 서브트리는 재사용하고 나머지는 버립니다.
- 다음 행동 하나만 실행합니다.

**계산 예산**
- 박스당 결정 예산은 라인 속도로 정해집니다(예: 8 s/박스 → 수 초).
- Python 시제품은 시나리오 평가만 결정당 1~2 s라서, 깊은 트리는 C++ 이식이나 병렬화가 필요할 수 있습니다. 실측으로 정합니다.

## 4-1. AI로 탐색량 줄이기
| 방법 | 내용 | 줄이는 것 |
|---|---|---|
| ① 정책망 | 먼저 펼칠 후보의 **순서**를 정합니다. 고정 개수로 자르지 않고 점진적으로 늘리며, 낮은 순위 후보도 일부 탐색합니다(낯선 분포에서 정책 의존도 완화) | 가지 수 |
| ② 가치망 | 몇 단계 뒤 상태의 최종 결과를 바로 예측. 미입고 수량을 입력으로 넣어 미래 평균을 직접 예측 | 깊이, 시나리오 수 |
| ③ 선택적 탐색 (**기본 꺼짐**) | 신경망 확신도와 실제 정확도는 다를 수 있으므로, 별도 실험으로 손실·실패율을 확인한 뒤 켭니다. 켜더라도 제약·로봇 검증은 생략하지 않습니다 | 탐색 횟수 |
| ④ 전문가 반복 | 깊은 MCTS 결과를 정책망이 따라 하도록 오프라인 학습 → ③에서 탐색이 필요한 경우가 점점 감소 | 장기 감소 |
| ⑤ 재사용 | 서브트리 재사용, 팔레트 상태 해시로 결과 캐시 | 중복 계산 |
| ⑥ 빠른 거르기 | 가망 없는 후보를 비싼 검사(하중 누적·IK) 전에 제외. **최종 실행 후보는 항상 정식 검사** | 검사 비용 |
| ⑦ 시간 배분 | 곧 집힐 박스에 계산 집중 | 낭비 |

- **도입 순서**: 학습 없는 탐색 기준선 → 순위(사전확률) → 가치망 → (실험 후) 선택적 탐색. 기능을 하나씩 추가하며 효과를 분리 측정합니다.
- **검증**: 같은 시간 예산에서 AI 없는 MCTS와 품질·계산량을 비교합니다.

## 5. 평가·AI·보상·최종 지표 분리
| 구분 | 역할 |
|---|---|
| 빠른 평가 (빈틈·높이·하중 여유·이동시간, 팔레트 크기로 정규화) | 후보 우선순위, 시뮬레이션 기본 정책 |
| 미래 시나리오 결과 | 탐색 내부 비교 |
| **학습 보상 / 학습 정답** | 시뮬레이션에서 **실현된** `J` 증분, 팔레트, 미처리 |
| 최종 지표 | 학습에 안 쓴 시험 세트 |

**AI: 가치·순위 모델 지도학습 (사용자 결정)**
- **입력**: 현재 적재 상태(높이맵 등), 버퍼, 보이는 박스, 남은 SKU 수량, 후보 행동
- **출력**: ① 후보 순위(사전 확률) ② 이후 결과 예측(가치)
- **학습 데이터**: 오프라인 시뮬레이션과 MCTS 결과(행동별 실현 결과)
- **출발점**: 동한 님 `DualHeadRanker`(LambdaRank + 회귀) 구조. 입력·출력 정의는 위에 맞게 재정의
- **기존 자산**: 태현 님 PPO와 동한 님 기존 모델은 비교 기준으로 보존합니다. PPO를 사전 정책으로 재사용할지는 행동 정의를 확인한 뒤 비교해서 결정합니다.

## 6. 실행: 마감 시각과 검증된 행동
```
t_commit = t_arr(집기 구간 도착 예상) − (상세 검증 + 명령 전달 + 여유)
① 이동 중: 탐색 + 실행 가능본의 1~2순위 행동을 백그라운드에서 상세 검증
② t_commit: 실행 가능본 최선 행동 확정 → 행동·공간 잠금 → **예정 상태 반영(6-1)** → 명령
③ 나머지 계획 계속 개선
④ 결과 → StateManager 갱신 → 계획 버전 증가
```
- **검증된 행동이 없으면**: 대기·정지·예외 처리로 넘어갑니다. 검증 안 된 후보는 실행하지 않습니다.
- **고정과 삭제의 구분**: 픽업존 박스는 최적화에서 고정할 뿐 상태에서 삭제하지 않습니다(예약 공간·버퍼 반영).
- **측정 지표**: 결정 지연, 마감 초과, 검증 실패, 오래된 계획 폐기 횟수
- **StateManager 계약**: 계획 버전, 실행 중 행동, 결과 확정 시점

## 6-1. 상태 확정: 2단계 (예정 / 확인)
| 상태 | 반영 시점 | 용도 |
|---|---|---|
| 예정 상태 | **행동을 확정한 순간** (공간 잠금) | 다음 계획의 기준 (파이프라인) |
| 확인 상태 | 놓은 뒤 측정으로 확인된 순간 | 기록, 하중 누적, 출하 |

1. 계획은 예정 상태 기준으로 세웁니다.
2. 실행은 의존 박스(받침)가 **확인 상태**일 때만 합니다.
3. 결과가 예정과 다르면 실측으로 수정하고 영향받는 계획을 무효화한 뒤 재계획합니다. **의존성 추적 범위**: 받침 관계, 주변 배치 공간, 로봇 접근 경로, 누적 하중·전체 무게중심, 버퍼 예약, 다음 행동 시작 시각.
5. 예정 상태의 박스는 적재 완료 수량, 출하 기록, 하중 확정에 넣지 않습니다.
4. 계획 버전은 확정 시와 확인 시에 각각 올리고, 오래된 버전의 명령은 거부합니다.

## 7. 예외
- **비교 방식**: 가능한 대안(버퍼 맡기기 / 버퍼 박스 먼저 / 제한된 재적재 / 팔레트 교체)을 `J`로 비교합니다. 고정 순서는 없습니다.
- **재적재 (초기 범위)**: 맨 위의 접근 가능한 박스 1~2개만 대상입니다. 꺼내는 순간, 임시 보관, 다시 놓기의 모든 중간 상태를 검증합니다.
- **교체해도 안 되는 경우**: 큰 박스, 집기 불가, 도달 불가, 센서 신뢰 불가 등은 보류 → NG → 작업자 확인으로 넘깁니다.
- **오래 기다린 박스**: 안전한 자리가 있을 때 우선 처리합니다. 제약은 완화하지 않습니다.
- **배치도 대기 상한**: 받침 박스 대기 시간과 버퍼 점유에 상한을 두고, 넘으면 배치도를 수정합니다.

## 7-1. 박스 옮기기 (재적재·버퍼 박스 이동) — 기회형 (사용자 결정 2026-10-09)
- **놓을 곳이 없을 때만이 아니라**, 매 결정에서 행동 후보로 함께 비교합니다. 이득이 클 때만 수행합니다(버퍼와 같은 방식).
- **비용에 반영할 것** (모두 J의 작업시간·정지시간으로 들어가며, 중복 가산하지 않음):
  - 로봇 동작 시간(집기 + 이동 + 놓기 × 박스 수)
  - **그동안 멈추는 다른 작업**: 현재 박스 대기, 도착 간격 초과 시 컨베이어 정지, 뒤 박스 연쇄 지연
  - 임시 보관 시 버퍼 이동과 칸 점유 손해
  - 이동마다 상세 재검증 시간
- **실행 조건**: 같은 미래 시나리오들에서 `이득 = J(그대로) − J(재적재 후)`를 계산해 **이득 하한 > θ**이고, 꺼내는 순간·중간·놓은 뒤 **모든 중간 상태가 안전**할 때만 수행합니다.
- **계산량 관리**:
  - 대상: 위에 아무것도 없는 박스 일부, 옮길 자리는 상위 몇 곳
  - 우선 평가 상황: 좋은 자리 없음, 큰 빈틈, 버퍼 포화
  - 이후 학습 모델이 이득 가능 상황을 먼저 골라 줍니다.
- **현재 상태**: 팀 시뮬레이터 `repack.py`는 "놓을 곳이 없을 때만, 현재 박스 부피 − 이동시간 ≥ min_gain" 규칙입니다. 위 방식으로 교체해야 합니다.

## 7-2. 다음 박스가 올 때까지 현재 박스를 못 놓았을 때 (축적 컨베이어 가정 없음)
**기본 가정**: 집기 구간 앞에 박스가 대기할 수 없습니다(`queue_capacity = 0`).

**정지의 전제조건** (현장 입력, 없으면 이 대응은 쓸 수 없음):
- 컨베이어·상류 투입 정지 가능 여부
- 정지 지연과 정지 거리
- 박스 간격이 정지 거리를 수용하는지
- 정지·재개 후 ID와 위치 추적 가능 여부

"다음 박스 도착 전 정지"는 정지 지연과 이동거리로 계산합니다. **미리 관측 가능한 박스 수(`preview`)와 물리적 대기 가능 수(`queue_capacity`)는 별개 설정**입니다. 어떤 작업장에서든 공통으로 쓰는 수단은 **컨베이어 정지·재개**이고, 정지 시간은 작업시간 손실로 J에 들어갑니다.

| 단계 | 조건 | 대응 |
|---|---|---|
| 0 예방 | 평소 | 박스별 시간 여유(= 다음 도착 간격 − 계획 로봇 작업시간)를 계산합니다. 시간이 드는 행동(버퍼 이동·재적재)은 **유발할 컨베이어 정지 시간까지 J에 포함**해 비교합니다. 비상용 버퍼 1칸을 유지합니다. |
| 1 컨베이어 일시 정지 | 다음 박스 도착 전 처리가 안 끝날 것으로 예측 | 도착 전에 미리 정지(HOLD) → 처리 후 재개. 도착 예정 시각을 정지 시간만큼 갱신 |
| 2 빠른 모드 | 정지가 반복되거나 누적 정지 시간이 기준 초과 | 버퍼 이동·재적재 억제. 탐색 축소는 **계산이 병목일 때만** 효과가 있으므로, 계산 시간과 로봇·컨베이어 시간을 따로 측정해 원인을 구분 |
| 3 현재 박스 빼 두기 | 자리가 없어 집기 구간을 막음 | 버퍼(비상칸 포함)에 맡겨 집기 구간을 비우고 재개 |
| 4 공간 확보 | 버퍼도 가득 | 정지 상태에서 팔레트 교체 또는 재적재 |
| 5 작업자 호출 | 시간 상한 초과 또는 실패 반복 | NG 또는 작업자 확인, 원인 기록 |

- **축적 컨베이어가 있는 현장**: `queue_capacity ≥ 1`로 설정하면, 그 개수까지는 정지 없이 흡수하고 넘으면 1단계로 갑니다. 알고리즘은 같고 설정만 다릅니다.
- **교착 방지**: 박스별 대기 시간 상한을 넘으면 3 → 4 → 5단계로 강제 이행합니다(제약은 완화하지 않음). 버퍼에 넣을 때 "나중에 놓을 가능성"을 평가해, 낮으면 교체나 NG를 고려합니다.
- **지표**: 컨베이어 정지 횟수·누적 시간, 시간 여유 부족 예측 정확도, 빠른 모드 전환, 단계별 발생 횟수

## 7-2b. 로봇 작업시간 모델 (중복 없이)
- 모든 동작 시간은 **하나의 시간 모델**로 한 번씩만 계산합니다. 모델은 팀 `pac_robot_check.RobotFeasibility.cycle_time`입니다: HDR50-22 관절 속도 한계 × 0.5, 수직 접근·이탈 0.25 m/s, 집기·놓기 0.5 s.
- **행동별 시간**: 놓기 = cycle(픽업 → 자리), 맡기기 = cycle(픽업 → 칸), 꺼내기 = cycle(칸 → 자리), 재적재 = Σ cycle(원위치 → 새 위치)
- **대기·정지**: 이 동작들이 도착 간격을 넘긴 결과로 계산하며, 따로 더하지 않습니다.
- **고정 상수 제거**: 지금의 고정 상수(버퍼 0.5, 재적재 12 s, 놓기 8 s)는 이 모델로 대체합니다. 상수와 모델을 같이 쓰지 않습니다.
- **용도 구분**: 자리 점수의 T 항목은 후보 순위용(거리 근사, 상위 후보만 IK)입니다. J는 시나리오에서 실제 동작 시간을 합산합니다. 평가용 시뮬레이터도 같은 모델로 교체합니다.

## 7-3. 0.3 g 하드 검사 = 기둥(스택) 전체 기준
- 새 박스를 놓을 때, 그 박스에서 팔레트 바닥까지 **각 접촉면마다**, 그 위에 있는 모든 박스의 합성 무게중심과 높이로 0.3 g 수평 가속 시 합성 무게중심이 그 접촉면의 받침 다각형 안에 남는지 검사합니다.
- **예시**: 폭·높이 30 cm 박스를 4단 기둥으로 쌓으면 15 ÷ 60 = 0.25 g로 불통과입니다. 박스 하나 기준(1.0 g)으로는 잡히지 않습니다.
- 맞물림(두 개 이상에 걸침)은 받침 영역을 넓혀 통과에 유리합니다.
- 통과한 자리 사이에서는 비선형 점수(φ)로 효율과 경쟁합니다.
- **3단계 검사**
  1. **합성 무게중심 검사** (매 후보, 하드): 새 박스 아래 하중 경로의 접촉면만 증분 재계산, 8방향
  2. **힘 평형 LP** (상위·경계 사례): 압축 전용 + 마찰 원뿔, 넘어짐과 미끄러짐을 함께 판정, 박스별 하중을 산출해 허용 하중과 연결
  3. **PyBullet 경사 시험** (검증용): 0.3 g 수평 = 경사대 약 16.7°
- **하중·마찰 반영 범위**
  - ①은 기하만 보며 넘어짐만 판정합니다.
  - ②는 접촉면별 누르는 힘(위 하중)과 **마찰 ≤ μ·누르는 힘**, 옆면끼리 받치는 힘까지 계산합니다.
  - ③은 물리 엔진이 동적 효과까지 자동으로 반영합니다.
  - 미끄러짐(특히 이웃 없는 가벼운 바닥 박스)은 ②가 담당합니다.
- **마찰계수**
  - ②③ 기본값은 **μ = 0.4** (골판지 0.3~0.5 범위의 보수값, **사용자 확정**)이고, 0.3 / 0.5 민감도를 함께 봅니다.
  - 현재 PyBullet 설정(박스-박스 0.64, 박스-팔레트 0.72)은 낙관적이므로 검증에 그대로 쓰지 않습니다.
  - 실물 보정은 `scripts/calibrate_friction_from_tilt.py`로 합니다(경사 시험에서 미끄러지는 각도로 μ 산출).
- **LP 여유 (사용자 확정)**: LP는 "가능한 힘 배치가 존재하는가"를 보므로 낙관적입니다. 0.35 g로 검사하고, ③ 비교로 여유가 충분한지 확인합니다.
- **모델링하지 않는 것**: 골판지 변형은 허용 하중 검사로 따로 막습니다. 랩 효과는 **범위 밖**입니다(사용자 확정, 랩 없이 0.3 g = 보수 조건).
- **박스별 허용 하중 (현재)**
  - 계산: McKee `BCT = 5.87·ECT·√(t·둘레)`, ECT 5000 N/m, t 3 mm, 안전계수 4 → SKU별 364~568 N (37~58 kg)
  - 하중 누적: 지렛대 분배로 맨 아래까지
  - 파손 감지 시 0 N
  - 미입고 박스: SKU 무게 범위 중간값
- **허용 하중 제안 (미결)**: `BCT_SKU × 습도·보관·편차 계수 ÷ 1.5`
  - SKU별 BCT 출처 순서: 공급사 시험값 → 사양서 등급 McKee → 기본 추정
  - 카탈로그에 값과 출처를 함께 기록하고, 현장 계수는 현장 프로필에 넣습니다.
- **근거 제시**: 기존 팔레트에서 ①②의 판정을 ③과 비교합니다. 놓친 위험(통과 판정인데 실제 붕괴)은 0에 가까워야 하고, 과도한 거절 비율도 함께 보고합니다.
