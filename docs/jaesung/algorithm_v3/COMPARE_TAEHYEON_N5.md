## 같은 점
- 둘 다 **미래 5박스 탐색 + 학습 없음 + 무거운 것 위 금지 끔**입니다.
- 시간 환산이 사실상 같습니다. 태현 `w_time 0.0005`/초 = 팔레트 1개 2,000 s, jaesung 계산식 = 2,368 s. 그래서 같은 비용 기준으로 맞추기 쉽습니다.

## 서로 보완되는 점

|---|---|
| 팀 코드(`pac_highlevel`)에 통합, 실시간 실행(`realtime.py`), 시연 연결 | 미입고 박스를 탐색에 사용 (현대 피드백의 "미입고 박스 활용") |
| 막힌 팔레트 마감 규칙 (30% 문턱 대체, 근거 있음) | 상류 계량·카메라 정보 계층 (무게 모르는 박스는 범위에서 뽑음) |
| 평평한 층 배치 (단순, 설명 쉬움) | 안정성 검증(PyBullet 0.3/0.5 g)과 기둥 0.3 g 검사, 근거 문서 |
| 팔레트 3종, 포장 종류, 환경 파일 | 현장 조건별 허용 하중, 실제 찌그러짐 채점, 현장 비용 계산식 |

## 제안
1. **기반은 태현 코드**로 합니다. 이미 팀 런타임·실시간·시연에 붙어 있기 때문입니다.
2. jaesung 쪽에서 옮길 것 (효과를 하나씩 따로 측정):
   - ① 미입고 수량 기반 미래 순서 뽑기 + 최악 반영
   - ② 정보 계층 (계량 3 + 카메라 2): 카메라 5개 모두 무게를 안다는 가정을 현실화
   - ③ 박스별·현장별 허용 하중
   - ④ 안정성: 기준 확정 후 0.3 g 검사 또는 안정성 AI
   - ⑤ 끝 상태 평가를 시간 단위 J로 통일
3. **같은 데이터, 같은 지표로 직접 비교**: 태현 최종(N5L) vs jaesung `la_k3` vs 합친 버전. 팔레트, 시간, PyBullet 0.3 g, 찌그러짐을 봅니다.
4. 트리 탐색(MCTS)과 가치·정책 AI는 이 합친 버전 위에서 진행합니다.
