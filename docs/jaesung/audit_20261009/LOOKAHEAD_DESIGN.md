# 안정성 우선 미리보기(look-ahead) 적재 알고리즘: 설계 (시제품)

작성: 2026-10-09
- **출발점**: 사용자 요구와 아이디어 제안서(미래 시나리오 기반 적응형 Mixed Palletizing AI)
- **코드**: `lookahead.py`(플래너), `run_eval.py`(평가)
- **조건**: 팀 레포는 수정하지 않고, 팀 후보 생성기·하드마스크·상위 세계를 가져다 씁니다.

## 1. 요구사항 (사용자)
1. **안정성 최우선.** 단, 안정성이 일정 값을 넘으면 그 이상은 가중치가 줄어드는 비선형 점수식으로 만듭니다.
2. **계량 구간에서 CCTV로 박스 규격과 무게를 라벨링**합니다.
   - 컨베이어를 따라 오는 동안 미리 계산합니다.
   - 새 박스가 관측되면 그 정보도 반영합니다.
   - **계량 구간은 최대한 상류로 뺍니다.** 정보를 일찍 모을수록 미리 아는 박스가 늘어납니다.
3. 미입고 박스(남은 수량)를 고려합니다.
4. 효율은 팔레트 적재 효율과 작업시간을 함께 봅니다. 팔레트는 재활용되므로 팔레트 가격으로 비교하지 않습니다.

## 2. 정보 단계
| 단계 | 박스 | 플래너가 아는 것 | 사용법 |
|---|---|---|---|
| 0 | 집기 위치의 현재 박스 | 실측 규격·무게 | 실제 결정 |
| 1 | 계량을 마치고 이동 중인 k개 (`preview_k`) | **실측 규격·무게 + 순서** | 순서 그대로 가상 적재 |
| 2 | 계량 전 상류 CCTV에 보인 m개 (`preview_m`) | 규격·순서, 무게는 SKU 범위 | 시나리오마다 무게 샘플링 |
| 3 | 나머지 | SKU별 남은 수량 | 순서를 여러 개 샘플링 |

- **저울 위치와 k의 관계**: 현재 작업셀은 저울 중심(x = −3.80 m)에서 집기 스토퍼(x = −0.845 m)까지 약 2.95 m라서, k가 대략 3~6입니다.
- **실험에서 k를 0~10으로 바꾸는 이유**: "저울을 상류로 몇 m 빼면 얼마나 좋아지는지"를 수치로 보이기 위해서입니다.

## 3. 결정 방식 (rolling horizon)
1. **후보 생성 + 하드마스크(팀 코드)**: 겹침·돌출·높이, 박스별 무게 규칙(공식 문구), 압괴, LBCP를 검사합니다. 여기서 탈락한 후보는 점수와 무관합니다.
2. **루트 행동 후보**를 만듭니다.
   - 현재 박스를 상위 K개 자리 중 하나에 놓기
   - 버퍼 박스 꺼내 놓기
   - 현재 박스를 버퍼에 맡기기
3. 각 행동에 대해 **시나리오 N개를 샘플링**합니다. 1단계는 그대로, 2단계는 무게만 샘플링, 3단계는 남은 수량에서 순서를 샘플링합니다.
4. 각 시나리오에서 H개 박스를 빠른 기본 정책으로 가상 적재합니다. 놓을 곳이 없으면 막힘 비용을 더합니다.
5. **행동 비용** = 루트 비용 + γ × [(1−κ)·평균 + κ·최악]
   - 제안서의 F(평균 미래), R(나쁜 시나리오·막힘)에 해당합니다.
6. 가장 싼 행동 **하나만** 실행하고, 새 박스가 라벨링되거나 상태가 바뀌면 다시 계획합니다.

**계산 시간**
- 결정당 약 1.2초 (Python, K = 4, N = 4, H = 4).
- 박스가 계량 구간에서 집기 위치까지 이동하는 동안 계산하므로, 집기 시점의 지연과는 분리됩니다.
- C++ 이식이나 병렬화로 줄일 수 있습니다.

## 4. 점수식 (낮을수록 좋음): 안정성 우선, 비선형

**안정성 지수 S ∈ [0, 1]** = 0.20·지지율 + 0.25·맞물림 + **0.40·충격 내성** + 0.15·옆면 지지

- **맞물림**: 바닥 박스는 1, 아래 박스 하나에만 올라간 박스(기둥)는 0, 아래 박스 두 개에 반반 걸치면 1입니다(= 2 × (1 − 최대 분담)).
- **충격 내성**: 박스가 옆으로 몇 g까지 흔들려도 넘어지거나 미끄러지지 않는지(임계 가속도 a_c)를 목표 0.3 g(지게차 취급 수준)으로 나눈 값입니다(최대 1).
  - 넘어짐: 무게중심을 a·h만큼 옮겼을 때 받침 다각형 밖으로 나가는 최소 a입니다(4방향, 이분 탐색).
  - 미끄러짐: 마찰계수 μ = 0.4 g입니다.
  - 그 방향에 벽이나 이웃 박스가 박스 높이의 절반 이상 있으면 막힌 것으로 봅니다.
  - (v1에서는 이 자리에 "0.2 g 기울임 여유" 항을 썼습니다. `lookahead_v1_tilt.py`)

**하중 여유 L** = 1 − 최대 하중비

**비선형 반영**

```
φ(x; t, a_lo, a_hi) = a_lo·min(x, t) + a_hi·max(0, x − t),   a_lo ≫ a_hi
비용 = Σ w_e·효율특징 − φ(S; 0.75, 20, 2) − φ(L; 0.5, 8, 0.5)
```

- 목표(S = 0.75)에 못 미치면 1단위당 20의 손해를 보고, 넘으면 1단위당 2만 얻습니다.
- 그래서 **안정성이 부족한 자리는 거의 항상 지고, 충분한 자리끼리는 효율로 경쟁합니다.**

**효율 특징**: 높이, 윗면 높이, 표면 거칠기, 아래 빈 공간, 코너 거리, 무게 차단, 바닥 소모. 무게 차단·바닥 소모는 1~3단계 정보로 계산한 "남은 박스 중 더 무거울 확률"을 씁니다.

**팀 코드와의 관계**
- 동한 플래너(`pac_planning/scoring.py`)는 안전을 `min(1, 실제 ÷ 목표)`로 포화시키고, 안전 목표를 만족한 후보를 먼저 고릅니다. 비선형 아이디어의 거친(계단형) 버전입니다.
- 여기서는 목표 미만과 이상의 기울기를 따로 둔 연속형으로 만들었고, 맞물림·기울임 여유를 새로 넣었습니다.

## 4-1. 안정성 검증: 단계적 충격 시험 (`shock_test.py`)
- **방법**: 완성된 팔레트를 PyBullet에서 다시 쌓습니다. 0.1 → 0.6 g까지 단계별로 ±x, ±y 방향 수평 가속(각 0.4 s)과 수직 충격(1.6 g → 0.4 g, 지게차 들기·내리기)을 줍니다.
- **판정**: 박스가 20 mm 이상 밀리거나 10° 이상 기울지 않고 **버틴 최대 g**를 셉니다.
- **보고 지표**: 팔레트별 버틴 g의 중앙값·최솟값, 0.3 g 통과 비율, 0.5 g 통과 비율.
- **기준 참고**: EUMOS 40509는 0.5 g이고 랩을 감은 상태 기준입니다. 우리 시험은 랩이 없으므로 더 엄격한 조건입니다.

## 5. 효율 비교 기준 (팔레트는 재활용)
팔레트가 늘면 실제로 늘어나는 것은 **팔레트 교체·랩 감기 시간(셀)**과 **트럭 적재칸·출하 대기 공간(물류)**입니다. 그래서 두 물리 단위로 따로 봅니다.
1. **셀 처리량** (박스/시간): 놓기, 버퍼, 팔레트 교체 시간을 포함합니다. → **제약** (라인 요구값 이상)
2. **출하 효율** (박스/팔레트 → 1만 박스당 트럭 대수, 11톤 트럭 = T11 14칸 1단 가정) → 이 값을 **최대화**합니다.

팔레트 교체 시간(60/120/180초)에 따라 결론이 바뀌므로, 발표에는 민감도 표로 제시합니다.

## 6. 아직 튜닝하지 않은 것
- 효율 가중치는 수동 초기값입니다. 다음 단계로 CEM 튜닝을 합니다. 안정성 항(φ)은 설계로 고정하고, 목표는 "처리량 제약 하의 팔레트 수"입니다.
- K, N, H, γ, κ, 버퍼 비용도 수동값입니다.
